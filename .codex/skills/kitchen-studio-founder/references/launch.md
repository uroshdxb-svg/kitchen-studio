# Launch: a real validation experiment

Read the current validation brief, acquisition ledger and released-app readiness. Continue the selected first learning-pilot experiment; use public-source recruitment and exclude the user's network. Do not replace it with a friends-and-family test.

Before launch, define eligible operators, actual offer, required inputs, verified workflow, sample/exposure counts, observation method, time/effort cap and keep/change/stop criteria. A free pilot tests usability and usefulness; payment at a later price tests commercial demand. Keep both distinct.

Make prerequisites visible: sender readiness, recipient evidence, live destination, reliable save/export and actual session availability. An unverified integration stays out of the demonstration. Dates are proposed in Asia/Dubai unless a launch time was supplied; do not invent appointments or publish a countdown before readiness.

Prepare a small exact outreach batch through `$kitchen-studio-acquisition`. Release only within the user's actual authorization. After sessions, record real plans, completed tasks, unresolved assumptions, useful supplier handoffs and separate price/payment evidence. If reality contradicts a simulation, update the hypothesis.

Return one run sheet with owners, dependencies, failure recovery and review dates relative to the actual start. No automatic campaign, publishing, paid distribution or recurring monitoring follows from the plan.
