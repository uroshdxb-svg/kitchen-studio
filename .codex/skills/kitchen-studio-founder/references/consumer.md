# Consumer: objection rehearsal

Run six hypothetical operator scenarios from the actual target and known objections. Vary project stage, plan readiness, decision influence, current workaround, supplier help and device/time constraints. Do not invent representative population shares, income distributions or personal identities.

Label every scenario and its output `simulated`. Show the same exact supported pitch/offer to each. Ask what would block a trial, what proof is missing, which qualification question matters and what would make the workflow easier. Record negative cases, including an already completed fitout and someone without a usable plan.

Run these as separate sequential analytical passes. Do not claim independent respondents or launch a 100-agent panel. Independent-agent work is optional only when explicitly requested by the user or the task workflow; keep it bounded to the available runtime.

Return an objection table with scenario ID, hypothetical obstacle, proposed wording/proof, product risk and real-world validation question. Keep synthetic outputs out of the acquisition ledger's replies, qualification confirmations, pilot outcomes and payments.

Do not produce or report simulated buy-rate forecasts, statistical bounds, willingness-to-pay claims or price ranges. Never publish synthetic quotes as customers. Hand useful questions to Outreach and exact workflow hypotheses to CX for real sessions. Real evidence takes priority when it contradicts rehearsal.
